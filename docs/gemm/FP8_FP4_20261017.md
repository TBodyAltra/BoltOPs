# FP8 × FP4 grouped GEMM（2026-10-17）

新增公开入口：boltops.gemm.gemm_a8wfp4、grouped_gemm_a8wfp4。
分支 feat/fp8-fp4-grouped-gemm，基于 E8M0 修复 70bfbe9。
接口布局和示例见 [GEMM API](../ops/gemm.md)。

## 实现与范围

支持 E4M3 FN 激活、按 K 低/高 nibble 打包的 E2M1 权重；
激活 scale 分组 K32 或 K128，权重 scale 分组 K32。
uint8 是原始 E8M0 编码；FP32/FP16/BF16 是浮点缩放值。
kernel 通过位运算将 E2M1 精确扩展为 E4M3，执行每 K32 普通 tl.dot，
在 dot 后乘 A/B scale，并以 FP32 累加。无主机端解包/反量化；
不依赖 tl.dot_scaled 或之前单独重建的 LLVM translation 库。

提供 dense、等长 expert grouped、ragged expert grouped 输入；
支持空专家、跨 tile 专家、非连续正 stride、奇数 K、M/N 尾部、
预分配输出、BF16/FP16/FP32 输出。
ragged offsets 必须非递减、从 0 到 T；由调用方保证内容有效。
这是 grouped GEMM 单阶段接口，不包括完整 fused_experts 两阶段融合或路由生成。
当前为精度优先实现，未进行性能调优。

参考 ROCm/aiter 5c9f6431ecc34f28a2ab0acfbe248e31922e7c05：
aiter/utility/fp4_utils.py 的 E2M1 数值和 nibble 顺序，
及 gemm/basic/gemm_a8wfp4、moe/moe_op_gemm_a8w4 的布局约定。
具体 URL 见 boltops/gemm/triton/SOURCE.md。

## 实测

环境：node60，容器 kxu_pmd_8569_fp8_20261017，PMD gfx946；
Triton release/3.6.x 46f0bed3561364b63ba4046d9c8c0cb70380ea30。
使用原始构建 libtriton SHA256
6994eb9c35b54b71a8b2e2d05767bbef3a1d2ae07115e4b9ff67ac83122ae13c。

test/gemm/test_gemm_a8wfp4.py：15/15 PASS（13.25 秒）。
包括 16 种 E2M1 编码逐位验证、K32/K128、四种 A/B scale 存储组合、
独立 CPU 反量化后 matmul reference、ragged 空专家及跨 tile 分组、
非连续 stride、奇数 K、空输入、FP16 和 FP32 输出。
BF16 主回归 atol=.05、rtol=.01；FP32 atol=1e-4、rtol=1e-5。

G472–G505 共 34 项按完整 M/N/K 和全部专家数单独验证，
激活 scale 按每项要求使用 E8M0 或 FP32，K32/K128 不做重复展开适配；
MXFP4 权重 scale 使用 uint8 E8M0（浮点存储另有单元测试）。
基准采用确定性的等长专家分组，不代表模型路由回放。
34/34 全部编译通过；完整尺寸精度队列现已暂停（2026-10-20），不能把编译通过记作精度通过。

moe_grouped_gemm/fp8e4m3xfp4e2m1_to_bf16/20261017-fp8fp4-support/
包含各项 compile/run 结果、precision.json、输入规格、TTIR/TTGIR/LLIR/

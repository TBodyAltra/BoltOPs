# FP8 dot 后乘 E8M0 scale 修复

版本基线：boltOps main 52f132a；Triton release/3.6.x 46f0bed35；node60 的 kxu_pmd_8569_fp8_20261017 容器，PMD 8569/gfx946。以下是模拟器结果，不是真机结果。

现有普通 dot 后乘 scale 路径把 uint8 E8M0 编码直接转换为整数数值，127 会被当成 127 而非 1.0。增加共享解码 helper：仅当矩阵操作数是 FP8 且对应 scale 为 uint8 时，将 E8M0 指数编码精确还原为 FP32；保留 code 0 的 2^-127 和 code 255 的 NaN。浮点 scale 和非 FP8 路径原样通过。

接入普通/预排布 block-scale GEMM、vLLM block-scaled FP8 GEMM、grouped MoE 的 regular/COMBINE_SCALE_LOAD/persistent 路径。仍采用每个 K 块 tl.dot 后乘已解码 scale 再累加，没有切到 tl.dot_scaled，不依赖原生硬件 scale-copy lowering。

同时修正 grouped FP8 wrapper 的 BK 裁剪：K tile 只受 scale 的 K 粒度限制，不能被 N 粒度 1 缩成 BK=1。INT8 分支保留原行为。grouped FP8 split-K 原有禁用限制保留，不属于新增支持。

验证：
- 新增解码/精度回归与原有相关测试合计 24/24 PASS。
- 全部 256 个 E8M0 编码逐位检查；浮点 scale 与非 FP8 uint8 scale 保持检查通过。
- 激活/权重单侧与双侧 E8M0，普通 GEMM split-K 1/2，grouped regular/combined/persistent 均通过。
- 原需求 G034，6×128×6144、激活 E8M0@1×128、权重 FP32@1×128、输出 BF16：767/768 mismatch → 0/768，max_abs=0、nonfinite=0，seed0 和原输入配置不变。
- 需求表其余完整尺寸验证继续单独进行，不能将上述回归当成全量通过。
